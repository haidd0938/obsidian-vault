# 00 体系总览

## 一句话
本机是**单一 Hermes Agent 体系**，多个入口（皮肤）共享同一套数据与技能——不存在"多个独立系统"。

## 入口清单

| 入口 | 端口/方式 | 进程 | 说明 |
|---|---|---|---|
| 桌面端 | Hermes App | Hermes | 主入口（当前会话） |
| hermes-web-ui | **8648** | node (hermes-web-ui) | 独立 Web UI，老板日常用 |
| Hermes Studio | **8748** | Hermes 内置 server | 桌面 App 内置 Web UI |
| CLI | 终端 `hermes` | hermes CLI | 命令行入口 |
| cron | 定时任务 | hermes scheduler | 自动任务（日报/快照等） |
| 移动云服务器 | 36.137.78.214 (8899) | 慧标云端 | 生产服务器（另见慧标档案） |

其他已知端口：8000 CreatorHub、8899 慧标后台、20128 OmniRoute（费用先探活）。

## 数据存储（核心）

| 数据 | 位置 | 说明 |
|---|---|---|
| 技能 | `~/.hermes/skills/`（文件系统） | 431 个 SKILL.md，改文件即生效 |
| 会话 | `~/.hermes/state.db`（1.2GB） | Hermes 本体会话库，所有入口共用 |
| 账号 | `~/.hermes-web-ui/hermes-web-ui.db` | Web UI 账号（admin） |
| 记忆 | `~/.hermes/memories/`（git 仓库） | MEMORY.md + USER.md，每日 23:30 快照 |
| 配置 | `~/.hermes/config.yaml` | 模型、工具、profile 配置 |
| 向量记忆 | `~/.hermes/mcp-memory/memory.db` + fact_store | 实体/信任分深度记忆 |

## 同步机制（为什么默认同步）

- **技能**：存在文件系统，所有入口直接读 → 改文件即全局生效
- **会话**：所有入口读写同一个 `state.db` → 一端开的会话，另一端刷新可见
- **账号**：共用同一 db → 同一个 admin 登录
- **本质**：8648 / 8748 / 桌面端都是"Hermes 的皮肤"，不是独立系统
- **唯一注意**：正在运行的老会话有启动快照，新会话/刷新即最新
